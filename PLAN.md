# Plan — lab-report extraction take-home

1. **Establish the baseline.** Read the schema and gold labels, run the supplied entry point where credentials permit, and record the exact model/setup. If the supplied API cannot be used, choose a reproducible no-key alternative and measure its unmodified baseline before changing extraction behavior; clearly separate measured results from unavailable measurements.
2. **Build a trustworthy evaluation.** Compare rows by test identity and numeric value (with a small documented tolerance), then score exact row matches plus value, unit, and reference-range fields separately. Inspect label quality and ordering/normalization differences before treating them as errors. Use only the eight labelled reports for quantitative gold scoring; manually inspect the four unlabelled reports and record limitations.
3. **Inspect representative failures.** Examine clean digital PDFs, multi-page/scanned PDFs, and phone-photo reports. Trace errors to root causes such as incomplete page coverage, image resolution/OCR, row association, or unsafe value/range assumptions. Select the three highest-impact categories using evidence from specific reports and rows.
4. **Make a small, general fix.** Preserve `python extract.py <file>` and schema-valid JSON. Prefer simple, testable changes (document conversion, extraction/normalization, validation) over a larger framework. Avoid report-specific rules and avoid inventing absent clinical ranges.
5. **Re-run the same evaluation.** Keep the scoring method and fixtures fixed, compare before/after quality, latency, and per-report cost, and report the actual environment/model. Measure repeated runs where feasible. Document one unsuccessful experiment and its observed result.
6. **Package the evidence.** Update the short README with findings, the three failure diagnoses, results, cost/latency, answers on RAG/fine-tuning/agents, setup/run commands, and a concise decision log. Keep commits incremental and do a final smoke test on reports not used for tuning.
